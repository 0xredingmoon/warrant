How a payment moves

Three parties, one transaction.

The agent never touches the money and never needs gas. It signs an intent; the relayer submits it; the vault checks every rule before a single token leaves.

  1. 1Signed by the agent this mandate names
  2. 2On the allowlist the owner wrote
  3. 3At or under the per-payment cap
  4. 4A rolling window, not a calendar day
  5. 5Within the total the mandate allows
  6. 6Not expired and not revoked

If any check fails → a PaymentRefused event is written on-chain with a reason code, and no money moves.

These are the six an owner sets. The contract also refuses a merchant past its own per-merchant caps, an invoice reference it has already seen, a payment larger than the vault holds, and one above the approval threshold.

OwnerFunds, approves, revokes, freezes. The only party that can withdraw.
VaultOne contract per owner. Every rule lives in it, not in the agent's prompt.
RelayerSubmits signed intents and pays gas. It cannot change what was signed.
AgentHolds a key and a mandate. No funds, no gas, nothing to drain.

The contract is the policy

The rules run inside the payment transaction. A compromised or prompt-injected agent can ask, but the vault decides, and it says why in a code the agent can read back.

The agent never needs gas

The agent signs an EIP-712 intent. A relayer submits it and pays the fee, so the agent key holds no funds and cannot be drained.

Merchants verify from chain data

A merchant serves a request after reading the payment event from the vault. Paid invoices build a receipt-bound reputation for the agent.

Integrate

Two lines to give an agent a budget.

The SDK wraps signing, relaying and error decoding, so an agent gets a spending limit the same way it gets an API key. A companion package, @warrant/mcp, exposes the same calls as MCP tools for agents that work through tool use.

agent.ts
import { WarrantAgent } from "@warrant/sdk";

const agent = new WarrantAgent({
  signer: agentAccount,
  publicClient,
  chainId: 44005,
  vault,
  mandateId: 1n,
  relayerUrl,
});

const r = await agent.pay({
  merchant,
  amount: "0.15",
  invoiceRef,
  context: { task: "ACME brief" },
});

// r.status: "executed" | "queued" | "refused" | "rejected"
// r.message: plain language, straight from the vault
// r.explorerUrl: the transaction, when there is one
